What every button and bracket does

Every component the article editor understands, its exact markdown syntax, how it renders on the live site, and where it's known to bite. Bookmark this tab — the CMS never links here on its own.

Structure

Headings

# through ###### for H1–H6, or the toolbar's heading buttons. H2 and H3 are also picked up automatically as entries in the sidebar table of contents shown next to the published article on wide screens — H1 and H4–H6 are not.

Lists

*/- for bulleted, 1. for numbered — or the toolbar's list buttons.

You type
* Expected Return
* Standard Deviation
* Beta

1. Fit the model
2. Validate walk-forward
Renders as
  • Expected Return
  • Standard Deviation
  • Beta
  1. Fit the model
  2. Validate walk-forward
⚠ Don't leave an empty bullet at the end of a list. Hitting Enter into a blank last item (especially with a soft line-break, Shift+Enter, inside it) is a known crash in the editor — you'll see a red "Cannot find a descendant at path…" screen. Press Backspace to exit the list instead of Enter, and if it does crash, your last saved version is safe — only the unsaved draft in the browser is lost.

Media

Images, GIFs, video

Drag a file straight into the editor to upload it and insert the reference — or write ![alt text](/uploads/filename.ext) by hand if it's already uploaded. Files ending .mp4, .webm, .mov or .ogg are automatically rendered as a native video player instead of an image — same exact syntax either way, the extension is what decides it.

You type
![Efficient frontier plot](/uploads/frontier.png)

![Walk-forward demo](/uploads/backtest.mp4)
Renders as

→ an <img> for the .png, a full <video controls> player for the .mp4 — captioned with the alt text underneath.

Code

Code blocks

Triple backticks with a language tag, or the toolbar's code-block button. Gets full syntax highlighting on the live site. Fenced code is one of the editor's native block types — its content is always kept byte-for-byte, immune to the escaping issue covered under Math.

You type
```python
def sharpe(returns, rf):
    excess = returns - rf
    return excess.mean() / excess.std()
```
Renders as
def sharpe(returns, rf):
    excess = returns - rf
    return excess.mean() / excess.std()

Runnable sketches

A js code block whose very first line is exactly // live. It ships as a playable p5.js sketch instead of a static snippet — plays automatically on page load, source hidden, with a Stop / Run toggle underneath. Runs sandboxed, so it's safe even mid-draft.

You type
```js
// live
function setup() {
  createCanvas(400, 200);
}
function draw() {
  background(20);
  circle(mouseX, mouseY, 40);
}
```
Renders as

→ a live canvas the reader can move their mouse over, right in the article, with a small ■ Stop button above it.

Math

Math

Inline with single $, display (its own centered line) with double $$. Both use standard LaTeX inside the delimiters.

You type
The Sharpe Ratio is $\text{SR}(w)$, defined as:

$$SR(\omega) = \frac{R_p - R_f}{\sigma_p}$$
Renders as

The Sharpe Ratio is SR(w), defined as:

SR(ω) = (Rp − Rf) / σp

✓ protected Display math ($$…$$ on its own line) is a dedicated "Math (display)" block — insert one fresh from the toolbar's + menu. It renders live with real KaTeX right in the editor, and its LaTeX is stored untouched, so it can't be corrupted by a save.
⚠ not protected Inline math ($…$ mixed into a sentence, a list item, a heading) is still ordinary text to the editor. If it contains _ or [ ] — subscripts and vector notation, mostly — a save in rich-text mode can quietly inject stray backslashes and break it (this is exactly what happened to the Markowitz article). See Raw-Markdown mode for the workaround.
Editor

Raw-Markdown mode

The body field's toolbar has a Rich Text / Markdown toggle. Markdown mode is a plain textarea bound to the exact source string — no round-trip, so nothing in it can get silently rewritten. Switch to it before typing or editing inline math, or before touching the last item of a list.

Rule of thumb Prose, headings, lists, images, code — rich-text mode is fine and faster. The moment you're placing a subscript or bracket inside a $…$ span mid-sentence, flip to Markdown mode for that edit, then flip back.

The preview pane

The pane on the right of the entry screen isn't Decap's generic markdown preview — it's the site's actual MarkdownBody component, the same code that renders the published page, reused verbatim. What you see there is what ships, math, code highlighting, runnable sketches and all. If something looks wrong there, it'll look wrong live — worth trusting it before you publish.

If something breaks

SymptomLikely causeFix
Red screen, "Cannot find a descendant at path…" Slate crash from a trailing empty list item Refresh the tab — your last save is intact. Re-add the lost bit in Markdown mode, don't leave the list open on a blank line.
An equation shows literal \_ or \[ after saving Inline math round-trip escaping (see Math) Fix the equation directly in the file or in Markdown mode; redo the edit there next time.
Preview pane is blank Empty body, or a malformed $$/code fence missing its closing marker Check every opening delimiter has a matching close.
